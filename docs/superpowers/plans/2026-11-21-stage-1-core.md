# Stage 1 (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a usable Private-mode Secret Santa: an organizer signs in, creates a drawing, draws, every
participant gets one email with a private link, links can be re-sent, and every drawing deletes itself 90
days after creation.

**Architecture:** One Cloudflare Worker serving server-rendered HTML plus a small script for the match page.
Three SQLite-backed Durable Object classes: `Drawing` (one per drawing), `Organizer` (keyed by lowercase
email) and `Registry` (single instance: templates, caps, drawing index and deletion work list). All rules
that can be pure live in `src/core/` and take randomness and the clock as parameters; the objects are thin
state machines around them. Emails are sent from the `Drawing` object's alarm, never from the request that
caused them.

**Tech Stack:** TypeScript, Wrangler, `@cloudflare/vitest-plugin`, Vitest, Workers runtime APIs
(Durable Objects SQLite storage, alarms, `send_email` binding, WebCrypto). No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-21-secret-santa-app-design.md`. Read it before any task. Section
numbers below (for example "spec 8") refer to it.

**Scope:** spec 17, stage 1, plus what that stage needs to be usable: organizer sign-in and saved people,
the create-drawing form, the Registry as deletion work list, default templates, caps enforcement at their
defaults, and the privacy page. Out of scope here (later plans): Display and Display & Email modes, splice,
redraw, the admin template editor, caps screen and admin list, the setup script.

**Where the build happens:** after the spec and this plan merge, open an issue for the Stage 1 build and
work on `dev/<issue>-stage-1-core` in `worktrees/`. One signed Conventional Commit per task. Never add AI
authorship trailers or "Generated with" lines.

## Global Constraints

- Every new source file starts with `// SPDX-License-Identifier: AGPL-3.0-only`.
- No real email, hostname, account, zone, application or identity-provider ID anywhere committed. Use
  `example.com` placeholders: host `santa.example.com`, sender `santa@mail.example.com`, organizers
  `organizer@example.com`, `admin@example.com`.
- Vocabulary: "drawing", never "game". "Session" only for sign-in sessions.
- `compatibility_date` on or after `2026-02-24` (spec 11: `deleteAll()` also clears the alarm).
- `workers_dev: false`, `preview_urls: false`, `observability.logs.invocation_logs: false`,
  `assets.run_worker_first: true`.
- No `console.log` (or any logging) of names, emails, assignments or tokens. No personal data or tokens
  in any URL path or query string.
- One recipient per message; never `cc` or `bcc`; both `html` and `text`; `from` is always the configured
  sender.
- Emails are stored and compared lowercase, after trimming.
- Randomness in production is `crypto.getRandomValues`; integers from it without modulo bias.
- Caps defaults: participants per drawing 50 (hard ceiling 100), active drawings per organizer 10,
  drawings created per organizer per day 10, organizer-triggered emails per organizer per day 300,
  self-resend 20 per participant per day and 2 × participant count per drawing per day.
- `delete_at` = `created_at` + 90 days (7,776,000,000 ms), fixed at creation.
- Tests: no tests of mocked behavior; the platform is never replaced by a mock. Pure code takes an
  injected `Rng` and `now`. Durable Object tests run in the Workers runtime with real bindings.
- Package versions verified on the npm registry on 2026-11-21: `@cloudflare/vitest-plugin` 1.9.0 (peer
  `vitest ^4.1.0 || ^5.0.0`), `vitest` 5.1.1, `wrangler` 4.166.0, `typescript` 7.0.2,
  `@cloudflare/workers-types` 5.20261121.1. Pin exact versions.

## Calls made in this plan (for the owner to check)

1. **"Per day" means the UTC calendar day** (`YYYY-MM-DD` of `now` in UTC) for every daily cap. The spec
   does not say; a calendar day is simpler to explain on screen than a rolling window.
2. **Sends run in the `Drawing` alarm**, not in the request. A draw or resend commits state and sets the
   alarm to now; the alarm sends. This keeps the request fast and makes crash recovery one code path.
3. **`{{match_link}}` is also refused in subjects**, alongside `{{recipient_name}}` and
   `{{pairing_list}}`, so a link never lands in provider-side subject logs.
4. **Route tests serve the Access signing keys from a test-only outbound handler** (Task 13). This
   replaces Cloudflare Access's public key endpoint in tests only; production code has no test path.
   The token verification itself is real WebCrypto against real keys. If the owner reads spec 16's "no
   platform mocks" rule as covering this, the alternative is to test routes only with a real Access
   application, which means live checks only.
5. **Organizer-facing output is checked for leaks by swapping the assignment** (Task 15): the same
   drawing with a different valid assignment must render byte-identical organizer output.
6. **A resend while a previous resend is still being sent is coalesced** (no new email), and a resend
   that ended `unknown` leaves both links usable until the next successful resend (spec 8 allows at most
   two live links).

## Review Focus

1. **Duplicate emails that differ only in case or surrounding spaces** (`Ann@Example.com ` and
   `ann@example.com`) must be refused as duplicates, in drawings and in saved people. Test in Task 3 and
   Task 9.
2. **HTML or script in a name, drawing name or budget** must arrive escaped in every HTML email and page.
   Test in Task 5 and Task 14.
3. **CR or LF in a drawing name** must never reach an email subject as a line break. Test in Task 5.
4. **A malformed, missing, voided or expired link fragment** must get the byte-identical response a wrong
   token gets. Test in Task 12.
5. **A request to a drawing past `delete_at` whose alarm has not run** must delete the drawing first and
   answer not found, for every entry point (match lookup, organizer view, resend). Test in Task 10 and
   Task 12.

### Task 2: Randomness and the draw

**Files:**
- Create: `src/core/random.ts`, `src/core/draw.ts`, `test/helpers/seeded-rng.ts`,
  `test/helpers/chi-square.ts`, `test/core/random.test.ts`, `test/core/draw.test.ts`

**Interfaces:**
- Produces:
  - `interface Rng { nextUint32(): number }`; `const cryptoRng: Rng` (buffers `crypto.getRandomValues`).
  - `randomInt(rng: Rng, n: number): number` uniform in `[0, n)` by rejection (no modulo bias).
  - `shuffle<T>(rng: Rng, items: T[]): T[]` (Fisher-Yates, returns a new array).
  - `interface DrawInput { n: number; excluded: ReadonlyArray<readonly [number, number]>; allowMutual: boolean }`
  - `type DrawResult = { kind: "ok"; recipientOf: number[] } | { kind: "impossible" } | { kind: "undecided" }`
    where `recipientOf[giver] = recipient`, indexes `0..n-1`.
  - `draw(input: DrawInput, rng: Rng, budget?: Partial<DrawBudget>): DrawResult`
  - `interface DrawBudget { sampleAttempts: number; searchNodes: number; exactCountMaxN: number }`,
    defaults `{ sampleAttempts: 200_000, searchNodes: 2_000_000, exactCountMaxN: 20 }`.
  - Test helper `seededRng(seed: number): Rng` (a small deterministic generator such as SplitMix32).

- [ ] **Step 1: Write failing tests** in `test/core/random.test.ts`: `randomInt(rng, 3)` over 30,000
  seeded draws has each value within 3% of 10,000; `randomInt` never returns `n`; `shuffle` returns a
  permutation of its input.
- [ ] **Step 2: Write failing tests** in `test/core/draw.test.ts`:
  - `"every result obeys the rules"`: for seeds 1..50 and sizes 2..30, both toggle settings, with 0, 1
    and n/4 random exclusion pairs: if `kind === "ok"`, `recipientOf` is a permutation, no fixed point,
    no excluded pair in either direction, and with `allowMutual: false` following `recipientOf` from 0
    visits all n before returning.
  - `"two people, toggle off, is impossible"`: `draw({ n: 2, excluded: [], allowMutual: false }, rng)`
    → `{ kind: "impossible" }`.
  - `"three people with one exclusion, toggle off, is impossible"`: n 3, excluded `[[0, 1]]` →
    impossible (a 3-chain uses every pair).
  - `"a person excluded from all but one other, toggle off, is impossible"` (degree below 2).
  - `"toggle on, no perfect matching, is impossible"`: n 4, person 0 excluded from 1, 2 and 3.
  - `"never a false impossible"`: a feasible chain instance built to defeat rejection sampling (n 12,
    a planted Hamiltonian cycle plus exclusions of every other pair for half the people) returns
    `"ok"` or `"undecided"`, never `"impossible"`; with `budget: { sampleAttempts: 1, searchNodes: 1 }`
    it returns `"undecided"`.
  - `"uniform"`: for n 4, 5 and 6, toggle on and off, with no exclusions and with `[[0, 1]]`, enumerate
    every valid assignment, run 20,000 × (number of valid assignments) seeded draws, and assert the
    chi-square statistic is below the 0.001 critical value for (count − 1) degrees of freedom
    (`chiSquareCritical(df, 0.001)` in the helper, Wilson-Hilferty approximation).
  - `"exact fallback is uniform"`: same test with `budget: { sampleAttempts: 0 }`, toggle on, n 5.
- [ ] **Step 3: Run** `npx vitest run test/core`. Expected: FAIL (modules missing).
- [ ] **Step 4: Implement `random.ts` and `draw.ts`.** Method (spec 7):
  - Allowed matrix: `i !== j` and the pair not excluded.
  - Toggle on: decide feasibility by bipartite matching (Kuhn's augmenting paths is enough at n ≤ 100);
    infeasible → `impossible`. Sample by uniform permutation (`shuffle`) accepted when every
    `allowed[i][p[i]]`, up to `sampleAttempts`. If exhausted and `n <= exactCountMaxN`, sample exactly:
    `count[mask]` = number of ways to give recipients outside `mask` to givers `popcount(mask)..n-1`,
    computed with `BigInt` over all masks, then choose each giver's recipient with probability
    proportional to the completion count. Otherwise `undecided`.
  - Toggle off: `n < 3` → impossible; any person with fewer than 2 allowed partners → impossible.
    Sample by fixing person 0 and shuffling the rest into a chain, accepted when every consecutive link
    (including last → 0) is allowed, up to `sampleAttempts`. If exhausted: run depth-first search for
    any Hamiltonian cycle with at most `searchNodes` node expansions; search finished with none →
    `impossible`; budget out → `undecided`; one found → keep sampling with a fresh `sampleAttempts`
    budget and return `undecided` if that also runs out (a found cycle proves feasibility but is not a
    uniform sample, so it is never returned).
- [ ] **Step 5: Run** `npx vitest run test/core`. Expected: PASS, and the suite finishes in under 60 s.
- [ ] **Step 6: Commit** `feat: add the uniform draw with proved impossibility`.
